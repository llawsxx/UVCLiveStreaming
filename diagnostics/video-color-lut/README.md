# 视频调色 LUT

## 使用

USB 摄像头界面的“视频调色（LUT）”默认关闭。开启后可实时调整曝光、对比度、白平衡色温／色调和饱和度，参数会保存，并同时应用于预览、录像和推流。全部参数处于中性值时直接旁路。“重置调色”保留输入 Transfer、输入色域和 LUT 精度。

输入 Transfer 和色域描述采集信号在 YUV → RGB 之后的 RGB 含义，需要与实际来源一致。它们与编码目标颜色设置、H.26x 元数据重写分别控制。调色不自动修改编码颜色标记，不执行输出色域转换或 HDR → SDR 色调映射。

## 数学和运行路径

烘焙顺序：输入 Transfer 解码到线性 RGB → 曝光乘 `2^EV` → Bradford 白平衡矩阵 → 围绕参考白 18% 的线性对比度 → 按输入色域的线性 Y 权重调整饱和度 → 裁剪到 0～1 → 用输入 Transfer 编码回 RGB。

- 曝光 −4～4 EV；对比度和饱和度 0～2。线性亮度偏移已移除，旧保存值不再读取并在保存设置时清理。
- 白平衡 2000～12000 K，6500 K／色调 0 为精确中性。提高色温使校正偏暖，正色调偏洋红。
- Transfer 支持 BT.709、sRGB、Gamma 2.2／2.4、Linear、PQ 和 HLG；色域支持 BT.709／sRGB、BT.2020、SMPTE 170M。
- PQ 的线性 1 对应 10000 nit，参考白 203 nit。HLG 使用逆 OETF 的场景线性量，参考白 0.26496256；不包含显示 OOTF。HDR 选项用于解释和调整输入，输出仍受现有表面和编码精度限制。

参数改变时由独立 CPU 工作线程生成 33³ 或 65³ 三维 LUT。待处理参数合并为最新一份，过时任务按蓝色切片取消。USB 回调不执行烘焙，也不等待烘焙完成。生成期间保留上一次完整的 LUT，第一次生成前为旁路。

GPU 使用二维纹理 atlas，在原有 YUV／RGB 着色器内完成三线性插值：两次纹理采样各自对红／绿双线性插值，再在相邻蓝色切片间插值。没有额外整帧渲染、CPU RGB 回读或图像缓存。预览和编码使用同一张已上传表。

33³ atlas 为 198×198，65³ 为 585×520；有半精度纹理和线性过滤扩展时使用 RGBA16F，否则使用 RGBA8。只在表改变时上传纹理。关闭／中性调色立即旁路，关闭渲染器会取消烘焙并释放 GL 资源。

LUT 是对完整数学变换的近似。33³ 为默认性能设置，65³ 在裁剪边界等位置更准确。删除线性偏移后，CPU 测试的一组 300 个 RGB 样本（sRGB、曝光 +0.4 EV、对比度 0.85、8000 K／色调 +8、饱和度 1.2）得到以下归一化通道误差，不能作为所有参数和图像的误差上限：

| LUT | 平均绝对误差 | 最大绝对误差 |
| --- | ---: | ---: |
| 33³ | 0.00048131 | 0.04192756 |
| 65³ | 0.00013480 | 0.00913441 |

移除偏移改变了采样点与黑色裁剪边界的相对位置，因此这组样本的最大误差增加；黑色附近的非线性曲线和硬裁剪使均匀 LUT 插值更困难。

## 验证结果（2026-10-05）

离线构建 `testDebugUnitTest`、`assembleDebug`、`assembleDebugAndroidTest` 成功。JVM 共 89 项，87 通过，2 项原有 RTMP 网络测试跳过，失败／错误均为 0。

以下真机 GPU 和性能数据来自删除线性偏移前的验证；此次删除同步更新 CPU 测试和编译 Android 测试，未重复真机测试。vivo V2338A 独立 `app_process` 测试通过：

- 33³／65³ atlas 输出与 CPU LUT 参考的差异不超过 2 个 8 位码值；验证了 sRGB、BT.709、PQ／BT.2020 和 HLG／BT.2020。
- 同帧预览表面与模拟编码输入表面像素一致。
- 关闭调色／全中性后输出与旁路基线逐像素一致，BGR 路径可调色。
- I420／P010 经范围转换后进入同一 LUT。
- 原有 GPU 范围／方向／BGR 和 4:2:2 色度／P010 低位回归通过。

33³ LUT 性能测试采用 off/on/on/off 顺序，每段 50 帧，前 10 帧预热；每种状态共 80 个有效样本。计时含复用 direct I420 缓冲上传、渲染、EGL swap 和 `glFinish`，ImageReader 获取／释放在计时外，不进行像素回读。开启参数：曝光 +0.35 EV、对比度 1.05、7200 K、饱和度 1.05。

| 分辨率 | LUT | 平均 ms | 中位 ms | P95 ms |
| --- | --- | ---: | ---: | ---: |
| 1280×720 | 关 | 2.892 | 2.800 | 3.627 |
| 1280×720 | 开 | 2.755 | 2.747 | 3.138 |
| 1920×1080 | 关 | 4.414 | 4.467 | 5.135 |
| 1920×1080 | 开 | 4.816 | 4.742 | 5.544 |
| 3840×2160 | 关 | 12.743 | 12.877 | 15.436 |
| 3840×2160 | 开 | 13.157 | 13.205 | 15.272 |

该次样本中 1080p／4K 平均增量约 0.40／0.41 ms；720p 差异处于测量波动内，不能解释为开启 LUT 更快。以上为单表面独立 GPU 管线数据，未包含 USB、MJPEG 解码、硬件编码或网络传输，也不代表最终串流帧率。未测量 65³ 性能和其他手机。

测试只将 APK／测试 APK／入口 dex 推送至 `/data/local/tmp/uvclive-video-color-lut`，通过 CLASSPATH 加载，没有安装或停止 APP。测试前后 APP PID 均为 20877。

## 重现独立 GPU 测试

构建两个 APK 后，用 `javac` 和 SDK D8 将本目录的 `VideoColorLutSmoke.java` 编译为 `classes.dex`，与两个 APK 一起推送到上述手机临时目录。无需安装或运行 instrumentation。

```sh
CLASSPATH=/data/local/tmp/uvclive-video-color-lut/classes.dex:/data/local/tmp/uvclive-video-color-lut/app-debug.apk:/data/local/tmp/uvclive-video-color-lut/app-debug-androidTest.apk app_process /system/bin VideoColorLutSmoke
```

在命令末尾增加 `benchmarkLutOverhead` 可只执行上述性能测试。入口通过反射执行 `VideoColorLutGpuTest`，默认执行三项调色 GPU 测试。原生转换回归另需 `DirectBufferSmoke` 入口和项目原生动态库。
