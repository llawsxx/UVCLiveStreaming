# YUV → RGB 高质量模式（2026-10-04）

USB 页面“YUV → RGB 矩阵”下增加“YUV → RGB 高质量模式”开关，默认关闭。USB UI 偏好与录制配置均保存该值。独立预览可以立即切换；录像/串流开始时选定，运行中开关禁用。

普通模式沿用双线性纹理采样。高质量模式使用 Catmull–Rom 双三次插值重建 U/V 色度，再应用所选矩阵及源范围。4×4 邻域的 16 点计算通过合并中间两个正权重优化为每个色度平面 9 次双线性纹理读取，负外侧权重保持独立。纹理边界采用 clamp-to-edge。

预览及编码 Surface 使用同一个 shader 和同一项设置；录像与串流共享编码，因此均生效。亮度 Y 保持原有采样；RGB/BGR 输入沿用原路径。高质量模式主要改善色度上采样，预览缩放不提供新的抗混叠缩小滤波。双三次核可能产生轻微过冲，最终 RGB 仍按原逻辑裁剪到合法范围。

P010 两字节均参与插值和高精度重建，保持前次修复的 10 位输入及对应 TV/Full range 计算。输出按用户此前选择仍为 8 位 RGB/编码，未增加 Main10 输出。

## 验证

- 全部 62 个 JVM 测试通过；Debug APK 和 AndroidTest APK 构建成功。
- vivo V2338A 使用独立 `app_process` 执行 7 个 GPU/编码测试，全部通过，没有安装 APK或停止 APP。
- `highQualityChromaMatchesIndependentCubicReference` 用独立 CPU 16 点核逐像素校验 GPU 9 次纹理读取的输出。覆盖 9×7 奇数尺寸、4:2:0/4:2:2/4:4:4/P010、Full/TV range、纹理边界；RGB 通道允许最多 2/255 的纹理插值/输出量化差异。
- 测试比较普通/高质量结果，确保开关实际改变像素；同帧预览与编码 Surface 逐像素相同，所有 16 次提交均成功。
- P010 低两位、原始格式转换、矩阵和范围、5 fps 预览不丢编码帧的回归通过。
- 在高质量模式下，实际 `c2.qti.avc.encoder` 和 `c2.qti.hevc.encoder` 分别编码三帧 YUV 测试图，均输出全部帧及正确的请求颜色参数。
- `git diff --check` 通过。

功能测试日志位于忽略的 `build/perf-diagnostics/yuv-high-quality/results.log`。采集卡持续 1080p60 的完整链路性能尚未测量，独立渲染性能比较见下节。

## 同日 GPU 渲染速度实测

在 vivo V2338A 上用独立 `app_process` 加载同一新版 APK，通过反射直接调用生产 `GpuVideoRenderer`。每种格式按普通/高质量/高质量/普通顺序运行（ABBA），每段预热 30 帧、计时 120 帧，每种模式共 240 个样本。使用可复用 direct buffer，输出到相同尺寸的一个 RGBA ImageReader Surface。

计时从 `render()` 开始，到 `glFinish()` 返回为止，包含纹理上传、EGL 切换、绘制、swap 及 GPU 完成等待，避免只计提交而忽略 GPU 执行。数据生成、缓冲区分配、测试帧构造、输出 Image 获取与释放不计入。没有第二次预览绘制，也不包含 USB、JPEG 解码、MediaCodec 编码或网络发送。逐帧 `glFinish` 同步限制了流水线重叠，因此这些是处理延迟，不能作为端到端 FPS。

| 输入 | 普通平均 ms/帧 | 高质量平均 ms/帧 | 高质量 P95 ms |
| --- | ---: | ---: | ---: |
| 1280×720 YUV420 | 2.0915 | 4.2640 | 5.5636 |
| 1280×720 YUV422 | 2.3100 | 4.6323 | 5.4705 |
| 1920×1080 YUV420 | 3.7359 | 7.4312 | 8.3122 |
| 1920×1080 YUV422 | 4.3775 | 7.0274 | 9.2618 |
| 1920×1080 P010 | 4.3834 | 9.0152 | 10.9089 |

每组 240 帧均没有超过 16.67 ms。开始和结束读取的 thermal status 都为 0，结束 skin 约 39°C；测试是在当前手机负载下短时连续运行，不能代表长时间温控后的表现。不同格式在不同时间窗口测量，不能据小幅差异推断某格式必然更快。

高质量模式在本次测试的耗时约为普通模式的 1.6～2.1 倍，单次渲染在 60fps 的 16.67 ms 周期内有余量。全帧率预览会增加另一次绘制；若优先保证录像/推流的 60fps，可使用已有的 5fps 预览，并观察实际近期 FPS。

测试启动器为忽略的 `build/perf-diagnostics/yuv-high-quality/YuvSpeedBench.java`，结果保存为 `speed-720-1080.log`、`speed-1080-422-p010.log`。测试没有安装 APK、停止或调整 APP 当前会话。
